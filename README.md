# ValueAreaReclaim

Самостоятельный пакет `@tradejs/strategy-value-area-reclaim` экспортирует
`strategyEntries` для TradeJS. Версия 1 работает на закрытых свечах `15m` и `1h`.
Она ищет неудачный выход из области основного объёма и возврат внутрь неё,
после чего ставит цель у POC, центра корзины с наибольшим объёмом.

Пакет создан по требованиям задачи. Источник идеи указан в
[Fade Break Volume Profile Fade Breakout Strategy](https://www.tradingview.com/script/1OnkbAiE-HVN-Fade-Break-Volume-Profile-Fade-Breakout-Strategy/).
Страница источника была недоступна при разработке, поэтому пакет не является
проверенным переносом Pine Script. Код написан самостоятельно.

## История 15m и исполнение 1h

Для `INTERVAL: "15"` ядро восстанавливает ограниченную историю из `data`
строго до текущей свечи и затем добавляет каждую закрытую свечу один раз.
Для `INTERVAL: "60"` оно получает те же исходные `15m` через новый метод
`strategyApi.getClosedCandles({ interval: "15", start, end, limit })`.
Часовые свечи используются только для распознавания возврата и ATR.

API привязан к символу и подключению текущего runtime. Полуоткрытое окно
`[start, end)` задаётся временем открытия свечей в миллисекундах UTC.
Граница `asOf` равна времени закрытия текущей свечи исполнения и фиксируется
до чтения данных. Каждая исходная свеча должна удовлетворять условию
`timestamp + 15m <= asOf`. Будущий запрос отклоняется до чтения.
Размер окна ограничен 1536 пятнадцатиминутными слотами, включая пропуски.

API возвращает свечи по времени, признак `complete` и интервалы пропусков
`missingRanges`. Повреждённые OHLCV и повторные timestamps отклоняются.
В BACKTEST и PARITY используется `cacheOnly: true`. CRON может получать
закрытую историю через обычное подключение с кэшем.

На `1h` ядро читает ровно `profileDays * 96` слотов завершённых UTC-дней
один раз за день и сохраняет только рассчитанный профиль. При неполном
окне или ошибке источника входы запрещены до следующей смены дня.
Коды причины равны `VAR_15M_HISTORY_INCOMPLETE` и
`VAR_15M_HISTORY_UNAVAILABLE`. Выход существующей позиции по сроку удержания
продолжает работать даже при ошибке источника.

Профиль не строится из часовых свечей, пропущенные `15m` не заменяются
свечами с нулевым объёмом. При одинаковых исходных данных дневные
POC/VAH/VAL и все корзины на `15m` и `1h` совпадают.

## Правила профиля

По умолчанию используются три завершённых UTC-дня. Время свечи считается
временем открытия в миллисекундах UTC. Профиль активного дня `D` использует
строго `[D - 3 дня, D)`. Текущий день исключён.

Профиль строится на первом обработанном закрытом баре с временем открытия
в новом UTC-дне, обычно на свече `00:00`, доступной в `00:15` для `15m` и в `01:00` для `1h`.
Последний бар с открытием до полуночи относится к предыдущему дню. Уровни не применяются задним числом к этому бару.
При запуске внутри дня профиль восстанавливается по тому же пути переходов.
Повторного расчёта внутри дня нет, даже если дневное окно неполное.

Границы профиля равны минимальному `low` и максимальному `high` всего окна,
включая свечи с нулевым объёмом. Диапазон делится на 48 равных корзин.
Объём каждой свечи распределяется равномерно по её `low–high`, пропорционально
длине пересечения с корзиной. Последняя пересечённая корзина получает остаток
округления. Сумма объёма сохраняется с точностью арифметики JavaScript.

Свеча нулевой ширины отдаёт весь объём корзине своей цены. Внутренняя граница
принадлежит верхней корзине, а максимальная цена профиля принадлежит последней.
Если весь диапазон нулевой, объём хранится в первой корзине, POC/VAH/VAL равны
одной цене и входы запрещены. При нулевом общем объёме профиля нет.

POC находится в центре корзины с наибольшим объёмом. При точном равенстве
выбирается нижняя корзина. Область объёма начинается с POC и расширяется
на одну соседнюю корзину за шаг. Выбирается сосед с большим объёмом,
при равенстве выбирается нижний. Если с одной стороны корзины закончились,
расширение идёт в другую. Пустые промежуточные корзины включаются.
Расширение заканчивается при достижении заданной доли общего объёма.
VAL равен нижнему краю области, VAH равен верхнему. Доля по умолчанию 70%.

Существующий `priceVolumeProfile` складывает весь объём свечи в одну из
24 корзин по типичной цене. `volumeStructure` распределяет объём по телу
и теням в 20 строках последних 180 баров и пропускает свечи нулевой ширины.
Оба текущих контракта возвращают POC, но не VAH/VAL. Их результаты здесь
не используются.

## Вход и сопровождение

Новое ожидание выхода разрешено, если предыдущее закрытие строго внутри
текущей области. Для LONG нужен `low < VAL`, для SHORT нужен `high > VAH`.
Вход появляется только при закрытии строго между VAL и VAH.
Выход и возврат могут произойти в одной закрытой свече. Само касание границы
возвратом не считается. Свеча, пересёкшая обе границы, отменяет ожидание,
поскольку порядок движений неизвестен.

На возврат отводится четыре следующих бара, включая четвёртый.
Более поздний возврат отменяется. Ожидание также отменяется при пропуске
свечи, смене дневного профиля или закрытии за противоположной границей.
После истечения срока продолжение движения вне области не запускает новое
ожидание. Для нового выхода требуется предыдущее закрытие внутри области.
Успешный пробой не создаёт позицию по направлению пробоя.

Цель равна POC профиля входа. Стоп для LONG расположен ниже минимума всего
выхода, для SHORT выше максимума. В экстремум входит свеча возврата.
Буфер равен `0.25 * ATR`. ATR считается как среднее последних 14 истинных
диапазонов закрытых баров исполнения, включая свечу возврата.
После пропуска свечи его накопление начинается заново.

Минимальное отношение ожидаемой прибыли к риску равно 1.5 после оценок
комиссии и проскальзывания. При цене входа `E`, стопе `S`, цели `T` и
односторонней оценке затрат `c` риск на единицу равен
`abs(E - S) + (E + S) * c`, прибыль равна `abs(T - E) - (E + T) * c`.
Перед расчётом проверяется правильная сторона стопа и цели.
`c = RISK_FEE_RATE + (RISK_SLIPPAGE_BPS + RISK_MARKET_IMPACT_BPS) / 10000`.
Объём позиции равен `MAX_LOSS_VALUE / риск на единицу`. Затраты исполнения
бэктеста задаются отдельно от этих оценок допуска сделки.
Поле `prices.riskRatio` общий runtime считает без затрат. Для проверки допуска
в сигнале сохранено `indicators.valueAreaReclaim.netRiskRatio` с учётом затрат.

По умолчанию разрешено одно решение о входе на направление за дневной профиль
и пауза восемь баров между решениями для обоих направлений вместе.
Ровно на границе восьми баров пауза ещё действует. Даже решение, позднее
отклонённое политикой host, расходует дневную попытку. Число попыток
сбрасывается в новом UTC-дне, а пауза сохраняется.

Открытая позиция сохраняет исходные стоп и цель при смене профиля.
Новые выходы за границы во время позиции не накапливаются.
Через 32 бара от решения о входе ядро возвращает `strategyApi.exit()`.
Ожидание возврата, пауза, ATR и удержание считаются в барах исполнения.
Например, 32 бара означают 8 часов на `15m` и 32 часа на `1h`.
TP/SL исполняет общий runtime. Если после холодного запуска обнаружена
позиция без восстановленного времени входа, ядро возвращает выход
`VAR_POSITION_WITHOUT_CHECKPOINT`. Время открытия позиции отсутствует
в текущем контракте `getCurrentPosition()`.

## Восстановление и ресурсы

`createValueAreaReclaimEngine({ initialCandles, config })` прогоняет историю
через те же переходы, что `next(candle)`. `getState()` возвращает полную
копию состояния с версией `value-area-reclaim/v1`. Для восстановления
передайте её как `checkpoint`; JSON-сериализация поддерживается.
Для чистого движка `1h` передайте также `profileForDay(day)`, возвращающий
заранее рассчитанный профиль из закрытых `15m` или `null` при его отсутствии.
Функция вызывается только при смене UTC-дня, включая начальную историю.
Уже сохранённый профиль после восстановления повторно загружать не нужно.
Несовместимые версия или конфигурация отклоняются.

Ядро хранит обычные сериализуемые объекты в `createStateController()`.
Ключ включает всю разобранную конфигурацию, чтобы разные ячейки сетки
не разделяли ожидания и ограничения входов. Для полного восстановления
нужны состояние движка, дневные попытки, пауза и время решения об открытии.
Движок сам не восстанавливает исполненные сделки из ценовой истории.
Холодный запуск без checkpoint не сохраняет прежние попытки входов.
Пакет не добавляет хранение состояния в Redis или на диск.

В памяти остаются максимум `96 * (profileDays + 1)` исходных свечей,
до 96 истинных диапазонов, 48 корзин и одно ожидание выхода.
На `1h` массив исходных свечей в состоянии пуст, после дневного расчёта
сохраняется только профиль. На обоих интервалах память ограничена.
`profileDays` ограничен диапазоном от 2 до 14. Пересчёт стоит
`O(profileDays * 96 * 48)` один раз за UTC-день.
Начальное чтение `data` выполняется один раз на новое состояние контроллера.
Повтор текущего timestamp не продвигает движок и не создаёт второй вход.
Более ранний timestamp отклоняется.

Figures содержат VAH, VAL, POC, период исходных данных, цену входа,
стоп и цель. Уровни рисуются с момента доступности профиля, а период
расчёта показан отдельной областью и UTC-аннотацией. Линии входа, стопа и цели
начинаются с момента решения и продолжаются на один бар исполнения. Это
проекция известных уровней; будущие свечи для неё не читаются.
Стабильный `setupId` связывает сигнал с исходным выходом за границу
и сохраняется после восстановления состояния.

## Проверка пакета и будущий бэктест

Нужны Node.js 24 и Yarn 4.13.0. Yarn PnP позволяет проверять пакет без
изменения общих `node_modules`. Новый API пока находится в исходном
framework и ещё не опубликован. Проверки используют публичный экспорт
`@tradejs/core/strategies` из собранного соседнего `investing`; TypeScript
берёт его актуальный контракт из `investing/packages/types/dist/index.d.ts`.
Реализация стратегии импортирует только публичные имена пакетов.
Установленный Project и его зависимости не подменяются.

Перед проверкой стратегии выполните в `investing`:

```bash
yarn workspace @tradejs/types build
yarn workspace @tradejs/core build
```

Затем выполните в каталоге стратегии:

```bash
yarn install --immutable
yarn checks
```

В `examples/backtest-grid.json` сохранена сетка из одной конфигурации,
в `examples/backtest-plan.json` заданы точное окно, USDT-инструменты,
прогрев и отдельная модель затрат исполнения. Вариант для `1h` сохранён
в `examples/backtest-grid-1h.json` и `examples/backtest-plan-1h.json`.
Он требует кэш `15m` для профиля и отдельный кэш `1h` для исполнения.
Подключение пакета в Project и импорт сетки в backtest-конфигурацию потребуют отдельного изменения.
Состав и runtime-конфигурация Project не менялись. Исследовательские прогоны
выполнялись из Project через отдельную загрузку пакета из исходников.
Для них использовались отдельные backtest-конфигурации Redis.
Для запуска `1h` host должен содержать согласованное расширение StrategyAPI.
Пакет `@tradejs/core@3.1.28`, использованный для первой версии, его не содержит.
Одних существующих npm-зависимостей без обновления framework недостаточно.

После подключения проверенного пакета и импорта сетки под именем
`ValueAreaReclaim:v1` будущий запуск из `tradejs-project` выглядит так:

```bash
TRADEJS_SOURCE_REPOSITORY_ROOT=/Users/aleksnick/dev/tradejs/tradejs-strategy-value-area-reclaim \
TRADEJS_FRAMEWORK_REPOSITORY_ROOT=/Users/aleksnick/dev/tradejs/investing \
yarn backtest -c ValueAreaReclaim:v1 -t BTCUSDT,ETHUSDT -f 15 \
  --startTime 1790121600000 --endTime 1792713600000 \
  --backtestPriceMode close --backtestEntryDelayBars 0 \
  --executionCosts '{"fees":{"makerRate":0.0006,"takerRate":0.0006},"slippage":{"baseBps":2,"spreadMultiplier":0,"marketImpactBps":0,"delayRiskMultiplier":0},"funding":{"enabled":false}}' \
  --cacheOnly --fast -p 1
```

Нулевая задержка и `close` обязательны для версии 1. Иные значения
отклоняются парсером. При отсутствии достаточного прогрева пакет ждёт
завершённые дни, поэтому холодный короткий запуск и срез длинного запуска
могут иметь разные результаты. Перед исследованием нужно зафиксировать
Git SHA пакета, framework и Project, сумму SHA-256 файлов конфигурации
и фактическое покрытие кэша. Результаты исследования относятся только
к зафиксированным правилам, данным и модели затрат.

Для будущего запуска `1h` используйте конфигурацию `ValueAreaReclaim:v1-1h`
и `-f 60` с тем же точным окном и моделью затрат. Профиль по-прежнему требует
историю `15m` от начала трёх завершённых дней перед стартом.

## Ограничения OHLCV

Равномерное распределение по диапазону свечи является выбранной моделью,
а не измеренным биржевым объёмом по цене. OHLCV не показывает путь цены,
очередность сделок и фактическое распределение объёма внутри свечи.
POC и границы области зависят от модели, числа корзин и длины окна.
Объём разных провайдеров и единиц измерения нельзя смешивать.
Вход по закрытию также не доказывает возможность исполнения по этой цене.
Стоп с буфером и расчётный риск не ограничивают потери при разрывах цены
или фактическом проскальзывании сверх заложенной оценки.

## Ограниченный исследовательский набор правил

По умолчанию используется исходный возврат `legacy`. Отдельно проверяются
`accepted-return` с четырьмя предыдущими закрытиями внутри того же профиля,
`rsi-double-trap` с двумя неудачными выходами и строгим расхождением цены
и Cutler RSI14, а также `prior-day-trap` с выходом и возвратом относительно
области объёма и диапазона предыдущего UTC-дня. Для последнего диапазон
и профиль используют одни и те же закрытые свечи 15m, в том числе при
исполнении 1h. Направленные режимы наследуют общий режим через `inherit`.
Это исследовательские варианты, их прибыльность не установлена.

## Исследовательский AI-gate для 1h

Пакет содержит локальный детерминированный фильтр `var-20261027-three-year-rounded-1`.
Он обучен на закрытых сделках режима `prior-day-trap` с исполнением `1h`
и профилем трёх завершённых UTC-дней из свечей `15m`. Для другого интервала,
режима входа или длины профиля фильтр отклоняет сигнал.

LONG допускается, когда POC находится не выше 35% ширины области от VAL,
а отношение прибыли к риску после оценки затрат не превышает 1.6.
Исходное ограничение ядра не ниже 1.5 продолжает действовать.
Для SHORT закрытие должно вернуться от VAH как минимум на 15% ширины области,
а расстояние от входа до стопа должно быть не меньше 1.2 ATR.
Все четыре границы включены. Отсутствующие или нечисловые используемые
признаки отклоняют сигнал. Допущенный сигнал получает качество 4;
правила качества 5 в этой версии нет.

Пороги зафиксированы до проверки последних 40% групп времени сигналов.
Для обучения использовались первые 60%, с исключением сделок, закрывшихся
после границы обучения. История уже участвовала в выборе ядра, поэтому
проверка остаётся ретроспективной. Фильтр имеет редкие сигналы и чувствителен
к порогам; его готовность к реальной торговле не установлена.

В `examples/backtest-grid-research-gate-1h.json` сохранена одна конфигурация
ядра этого исследования: риск 10 USDT, комиссия 0.06% и проскальзывание
2 bps на сторону. Для её повторения нужны кэши `15m` и `1h`, тот же
framework с причинным чтением закрытых свечей и отдельное имя backtest-сетки.
Project и его runtime-конфигурация автоматически не изменяются.

Raw-бэктест и проверка фильтра по его выгрузке являются отдельными этапами.
Отбор завершённых сделок не моделирует новые входы, которые могли бы
появиться после освобождения позиции. Результаты такого отбора требуют
отдельной проверки исполнения и общего ограничения капитала.
